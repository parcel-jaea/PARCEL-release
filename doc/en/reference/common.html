1.2 Solvers

PARCEL has the following seven solvers. The solver names are common to all languages. The algorithms are described in the “Linear Solvers” and “Eigenvalue Solvers” chapters of the User Guide, and how to choose among them in “Choosing a Solver”.

Solver Method Problem
pcg Preconditioned conjugate gradient method Ax=bAx = b with AA and the preconditioner matrix KK symmetric positive definite
pbicgstab Preconditioned stabilized biconjugate gradient method Ax=bAx = b (nonsymmetric matrices)
pgmres Preconditioned generalized minimal residual method (right preconditioning, with restarts) Ax=bAx = b (nonsymmetric matrices)
pcagmres Preconditioned communication-avoiding generalized minimal residual method (CA-GMRES). It generates ss basis vectors at once and orthogonalizes them by QR factorization Ax=bAx = b (nonsymmetric matrices)
power Power method One eigenpair of AA with the largest magnitude
inverse_power Inverse power method. At each iteration an inner linear solver solves Ay=xAy = x One eigenpair of AA with the smallest magnitude
ks_arnoldi Arnoldi process with Krylov-Schur restarts. Also handles nonsymmetric matrices and complex conjugate eigenvalue pairs Several eigenpairs of AA on the side of the largest magnitude; in shift-invert mode, the eigenpairs closest to the shift σ\sigma

The eigenvalue solvers handle the standard eigenvalue problem Ax=λxAx = \lambda x. When the spectrum of the preconditioned matrix is selected, they compute the eigenvalues of AK−1AK^{-1} instead of AA. Solvers can be excluded from the build (“Selecting the Solvers to Build” in the User Guide). What happens when an excluded solver is called is described in each language’s chapter.

1.4 Input Matrix

The coefficient matrix is given in CRS format. When solving in parallel with MPI, each rank owns a block of contiguous rows (nlocaln_{local} rows from the global row number nstartnstart) and passes only those rows. The format is explained in the data structure section of the User Guide.

  • The row pointer has length nlocal+1n_{local} + 1 and gives positions from the start of the owned rows. It is nondecreasing, and the difference between its last and first entries equals the number of nonzeros of the owned rows.
  • Column indices are global indices of the whole matrix.
  • Indices are 0-based. The C and Fortran APIs can also use 1-based indices.
  • The integers for the number of rows, the number of nonzeros, the row pointer and the column indices are passed as 64-bit integers (in C++ the integer type can also be made 32-bit at build time).

The library checks the following conditions; if they are not satisfied, all ranks report the same error (how errors are reported is described in each language’s chapter).

  • Each rank owns at least one row (a rank without rows is not supported). The number may differ between ranks.
  • The row blocks of all ranks together cover [0,nglobal)[0, n_{global}) without overlaps or gaps. They need not be in rank order.
  • The row pointer satisfies the conditions above, and the column indices lie in [0,nglobal)[0, n_{global}) ([1,nglobal][1, n_{global}] for 1-based indices).
  • The number of nonzeros of one rank, and the sum of its number of owned rows and its number of halo elements, fit in the range of the library’s internal local index (231−12^{31} - 1 or less with the default 32 bits). If they exceed it, increase the number of ranks (in C++ the local index can also be made 64-bit at build time).

The following conditions are not checked; if they are not satisfied, wrong results may be returned silently.

  • Store both the upper and the lower triangle even for a symmetric matrix (there is no format that stores only one triangle).
  • Store the diagonal element in every row (even if its value is 0). The Jacobi-type preconditioners use the diagonal elements.
  • Sort the column indices of each row in ascending order, and do not put the same column index twice in a row.

In a build without MPI, one process owns the whole matrix (all rows).

1.5.1 Notes on the Preconditioners

  • The block Jacobi preconditioner is slow on GPUs; on GPUs the Jacobi preconditioner is recommended. The types of preconditioners are described in the “Preconditioners” chapter of the User Guide.
  • The Jacobi preconditioner shares the row pointers and column indices of the coefficient matrix AA without copying them, and by default it does not keep the values of B=DA−1RB = D_A^{-1}R either but computes them from the values of AA at every application (the default of builds for A64FX stores the values). The preconditioner is built inside the solve and used only there, so do not destroy or modify AA while the solve is running. Building with -DPARCEL_JACOBI_ONTHEFLY=0 stores the values of BB, which uses more memory and makes the preconditioner faster on GPUs (“Choosing Between Memory and Speed” in the User Guide). With matrix scaling, and when the coefficient matrix, the preconditioner matrix or the preconditioner computation precision is double-double, the values are stored even with the default.
  • When the number of blocks and the scaling are automatic, the values actually used are printed if the environment variable PARCEL_PRECON_VERBOSE is set.
  • Scaling is not used with the point Jacobi preconditioner or without preconditioning.

1.5.2 Notes on the Eigenvalue Solvers

  • When the spectrum of the preconditioned matrix is not computed (default), the preconditioner settings are not used by the outer eigenvalue iteration. Specifying only the preconditioner does not make the eigenvalues of AA converge faster. To speed up the inner linear solver of inverse_power and shift-invert, set the preconditioner of the inner linear solver.
  • When the spectrum of the preconditioned matrix is computed, the inner linear solver (inverse_power, shift-invert of ks_arnoldi) becomes a right-preconditioned pgmres that solves (AK−1−σI)z=v(AK^{-1} - \sigma I)z = v and returns zz, and the preconditioner is KK itself (the settings of the preconditioner of the inner linear solver are not used).
  • The settings of the inner linear solver are used by inverse_power and by the shift-invert mode of ks_arnoldi, and not by power or ks_arnoldi without a shift. The orthogonalization of the inner pgmres is fixed to the modified Gram-Schmidt method.
  • The outer iteration continues even if the inner linear solver does not converge. The number of such cases is obtained as a result. It is not reflected in the outer convergence state.
  • In the shift-invert mode of ks_arnoldi without the spectrum of the preconditioned matrix, the inner pgmres solves (A−σI)z=v(A - \sigma I)z = v, and KinK_{in} is built from A−σIA - \sigma I. How A−σIA - \sigma I is given is described in each language’s chapter.
  • The error of the inner linear solver becomes the error of the eigenvalue estimate as it is, so the inner linear solver must converge more tightly than the outer toltol.

1.5.3 Q Modes and QR Factorization of pcagmres

The Q modes (constants) are as follows.

Mode Behavior
AUTO QQ is not formed only when the QR factorization is Cholesky QR and t=1t = 1; otherwise QQ is formed
EXPLICIT QQ is always formed (even for Cholesky QR with t=1t = 1)
IMPLICIT QQ is not formed for any tt. Only RR is obtained from the Cholesky factorization of the Gram matrix of the basis VV, and the solution is updated with V(R−1y)V(R^{-1}y). The QR factorization must be Cholesky QR or Cholesky QR by the moment method

The combination of the Q mode and the QR factorization is checked at the entry of the solve, independently of the order in which the settings are given, and the following cases are rejected (the same judgment on all ranks).

  • IMPLICIT with classical or modified Gram-Schmidt explicitly specified (if no QR factorization is specified, Cholesky QR is used).
  • Cholesky QR by the moment method combined with AUTO or EXPLICIT.
  • Cholesky QR by the moment method with a preconditioner other than none, or with ss that is not an even number of 2 or more.

Cholesky QR by the moment method (moment method) is only for symmetric AA. This is not checked; with a nonsymmetric AA a wrong RR is used and wrong results are returned. AUTO and EXPLICIT perform the same computation except for Cholesky QR with t=1t = 1. IMPLICIT computes in a different order, so its results differ within rounding errors even with the same ss, tt and QR factorization. With IMPLICIT, the orthogonality error of the Cholesky QR method is proportional to the square of the condition number of the basis, so a larger ss can worsen convergence. With FP16 data or arithmetic precision, do not use the Cholesky QR family (IMPLICIT and the moment method): the result is NaN or no convergence regardless of ss and tt (not checked). The methods are described in the “Linear Solvers” chapter and the “QR Factorization” chapter of the User Guide.

1.7.1 Output of Eigenvalues and Eigenvectors

  • power and inverse_power return one eigenvalue and one eigenvector. The eigenvalue is real.
  • ks_arnoldi returns kkeepk_{keep} eigenpairs in descending order of |θ||\theta| (closest to σ\sigma first in shift-invert mode). Convergence is guaranteed only for the first nevnev pairs.
  • An eigenvalue is given as a pair of real and imaginary parts. For a complex conjugate pair, the corresponding eigenvectors are stored consecutively as two vectors, the real part and the imaginary part.
  • If the run ends with an effective dimension below kkeepk_{keep}, the missing eigenpairs are returned as 0 (rank 0 reports this). Eigenvalues for which |θ|2≤10−300|\theta|^{2} \leq 10^{-300} in the inverse transformation of shift-invert are returned as +∞+\infty.
  • The layout of the arrays in each language is given in that language’s chapters.

1.8.2 Common Handling in the Linear Solvers

In the linear solvers (pcg, pbicgstab, pgmres, pcagmres), ∥b∥=0\|b\| = 0 returns x=0x = 0 without iterating, with the state CONVERGED_RTOL (iteration count 0; residual and true residual 0). Rank 0 writes the line ||b|| = 0 : x = 0.

If the relative initial residual ∥b−Ax(0)∥/∥b∥\|b - Ax^{(0)}\| / \|b\| of the initial guess x(0)x^{(0)} is below toltol (including the case where x(0)x^{(0)} is already the solution), every linear solver returns CONVERGED_RTOL without iterating (iteration count 0) and leaves xx at the initial guess. The residual and the true residual are this relative initial residual.

1.8.3 Standard Output

Rank 0 writes one line of the following form to standard output at the end of a solve (non-finite values are printed as n/a). inverse_power appends , linsolve_failures = ..., and ks_arnoldi appends , ks_nconv = <number converged>/nev (plus linsolve_failures in shift-invert mode).

Example: converged_reason = 1 (CONVERGED_RTOL) , its = 27 , residual = 4.200000e-10 , true_residual = 4.211375e-10

In addition, rank 0 writes the progress of the iteration and a breakdown of the computing time. The linear solvers write the true relative residual at termination on the line finish : residual true norm. pcagmres does not write this line when it returns at the check before the iteration. The format of the standard output is not part of the API. To obtain the results from a program, use the result interface of each language.

1.9 Settings and MPI

  • The settings are used when a solve is run. Give the same values on all ranks. Values outside the accepted values are rejected, and all ranks report the same error.
  • A solve is a collective operation (MPI_Barrier, MPI_Allreduce for inner products, and halo communication in SpMV). All ranks of the communicator with which the matrix is given must call it with the same solver and the same settings.
  • At the entry of a solve, the conditions on the input matrix, the size of the subspace of ks_arnoldi (including m≤nglobalm \leq n_{global}), and the combination of the Q mode and the QR factorization of pcagmres are checked. In every case, all ranks report the same error before any collective communication.
  • A solve does not report an error even if it does not converge. Check the convergence state before using the result. The convergence state is reset at the entry of a solve and set at its exit.
  • If device memory cannot be allocated, or the size of the matrix exceeds the range of the library’s internal integers, an error occurs. These can happen on only some ranks, so the handling differs between the languages (see each language’s chapter).
  • The dense LAPACK computations (ks_arnoldi) are done on rank 0, and the results are distributed to all ranks. All values used for decisions are aggregated over all ranks, so all ranks take the same branch.

1.10 Precision

PARCEL can choose the precision in which data are stored (data precision) and the precision of the arithmetic (arithmetic precision) separately for each operation (SpMV, preconditioner, vector operations, inner products) and each piece of data (matrix, vectors, preconditioner matrix, etc.). The types are half precision (FP16), single precision, double precision, long double, and double-double (about quadruple precision). How the precision is chosen differs between the languages.

Language Choosing the precision
C++ Template arguments for each operation and each piece of data (PARCEL Data Types)
C, Fortran Fixed by macros when the wrapper is compiled; cannot be changed at run time (all double precision by default). The input and output arrays are double precision
Python Double precision only

With configurations that use half precision, there is a lower limit on the relative residual that the precision can reach; with a tolerance below it, the iteration stagnates or breaks down with NaN. The details of the restrictions are given in “Specifying the Precision” in the “Usage” chapter and in “Numerical Accuracy and Reproducibility” of the User Guide.

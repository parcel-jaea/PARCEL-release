5 Usage

This chapter describes how to use the SYCL version of PARCEL from C++, C, Fortran, and Python. The description for each language is shown in tabs (the selected language is kept across pages and is shared with the language selection of the API Reference). The tab of each language is written so that it can be used by reading that tab alone. The sections for C++, C, and Fortran consist of the same items (setting the matrix, setting the vectors, setting the preconditioner, calling a linear solver, calling an eigenvalue solver, specifying precision, MPI decomposition, compiling and running, passing your own matrix), so corresponding items can be compared across languages. How to pass the matrix of your own problem to PARCEL (building CRS from triplets, reading a Matrix Market file, distributing to the ranks, choosing the partition) is in the last subsection, “Passing Your Own Matrix”, of the section for each language.

PARCEL itself is a C++ header library. From C and Fortran, the same 7 solvers as in C++ can be selected at run time and called through the bundled C API (capi/parcel_sycl_c.h, implemented in capi/wrapper_parcel_sycl.cpp) and Fortran module (capi/parcel_sycl_mod.f90). The differences between the languages are summarized below. Python calls the library through a native layer separate from the C / Fortran API; its differences are summarized in the Python section.

5.1 C++

5.1.1 Overview

Include Include/parcel_sycl.hpp and make the calls in the following order.

  1. Create an in-order sycl::queue and a parcel::comm (MPI communicator). Create the queue with the in_order property, as in sycl::queue q{sycl::default_selector_v, sycl::property::queue::in_order{}}; (the device is selected in the same way as with sycl::queue q;). The reason is given in the Quick Start. The check can be removed with -DPARCEL_REQUIRE_IN_ORDER=0, but this is not recommended.
  2. Register a matrix in CRS format to a parcel::matrix with set_crsMat().
  3. Create parcel::vector objects and copy values from host arrays with setValue().
  4. Create a solver class (parcel::krylov::pcg, etc.) and set the preconditioner, convergence tolerance, and maximum number of iterations.
  5. Call solver<...>() and copy the result back to the host array with getValue().

In a build with MPI, MPI_Init() and parcel::comm are required even when running with a single process (in a build without MPI, MPI_Init() is not needed and the communicator is created with parcel::comm comm(&q);; see “Build without MPI”). Linear solvers and eigenvalue solvers can share the same matrix object; the only difference in the call is the meaning of the second and third arguments of solver().

Below is a complete program that registers a row-partitioned 1D Laplacian (tridiagonal matrix), solves Ax=bAx=b with pcg, and then computes eigenvalues of the same matrix with ks_arnoldi. A similar example is in examples/example_pcg_ks.cpp.

#include <cmath>
#include <iostream>
#include <vector>
#include "./Include/parcel_sycl.hpp"

int main(int argc, char *argv[]) {
  MPI_Init(&argc, &argv);

  // SYCL queue: create it in-order (assumed by PARCEL)
  sycl::queue q{sycl::default_selector_v, sycl::property::queue::in_order{}};

  parcel::comm comm(MPI_COMM_WORLD,&q);
  int myrank   = comm.mpi_rank();
  int nprocess = comm.mpi_size();

  // ---- MPI decomposition: assign contiguous rows to each rank ----
  const PARCEL_INT n_global = 1000;
  PARCEL_INT nper = n_global / nprocess;
  PARCEL_INT nstart = nper*myrank;
  PARCEL_INT nend   = nper*(myrank+1)-1;
  if(myrank == nprocess-1){ nend = n_global-1; }   // the last rank takes the remainder
  PARCEL_INT n_local = nend - nstart + 1;           // number of locally owned rows

  // ---- Setting the matrix: CRS of the locally owned rows (row pointer: local, 0-based; column indices: global, 0-based) ----
  std::vector<PARCEL_INT> rowptr(n_local+1), col;
  std::vector<double>     val;
  rowptr[0] = 0;
  for(PARCEL_INT i = nstart; i <= nend; i++){
    if(i > 0)         { col.push_back(i-1); val.push_back(-1.0); }
    col.push_back(i); val.push_back(2.0);
    if(i < n_global-1){ col.push_back(i+1); val.push_back(-1.0); }
    rowptr[i-nstart+1] = (PARCEL_INT)col.size();
  }
  parcel::matrix<parcel_double> A(&q);
  A.set_crsMat<double>(&comm, nstart, nend, n_local, col.size(),
                       rowptr.data(), col.data(), val.data());
  // Note: at this point col and val have been rewritten to local indices

  // ---- Setting the vectors ----
  std::vector<double> x_h(n_local, 0.0), b_h(n_local, 1.0);
  parcel::vector<parcel_double> x(n_local,&q), b(n_local,&q);
  x.setValue(x_h.data());
  b.setValue(b_h.data());

  // ---- Linear solver (pcg) ----
  parcel::krylov::pcg<
    parcel_double, parcel_double, parcel_double, parcel_double  // Tspmv,Tprecon,Taxpy,Tdot
    > cg;
  cg.set_tolerance(1.0e-9);
  cg.set_max_iteration(10000);
  cg.set_precon_algo(parcel::PRECON_JACOBI);   // setting the preconditioner
  cg.set_jacobi(1);
  q.wait();
  cg.solver<
    parcel_double, parcel_double, parcel_double, // Tmat,Tvecx,Tvecb
    parcel_double, parcel_double, parcel_double  // Tvec,Tprecon_mat,Tprecon_vec
    >(A, x, b);
  x.getValue(x_h.data());  q.wait();
  if(!cg.is_converged()){           // solver() does not return an error even if not converged
    if(myrank == 0)
      std::cout << "pcg: " << parcel::krylov::converged_reason_name(cg.get_converged_reason())
                << " after " << cg.get_iterations() << " iterations" << std::endl;
    MPI_Abort(MPI_COMM_WORLD, 1);
  }

  // ---- Eigenvalue solver (ks_arnoldi): nev eigenvalues of largest magnitude ----
  const PARCEL_INT m = 30, k_keep = 10, nev = 4;
  parcel::krylov::ks_arnoldi<
    parcel_double, parcel_double, parcel_double, parcel_double
    > ks;
  ks.set_ks_subspace(m, k_keep, nev);
  ks.set_ks_max_restart(50);
  ks.set_tolerance(1.0e-9);
  ks.set_precon_spectrum(false);   // default. If true, gives the eigenvalues of A K^-1 with the K of set_precon_algo()

  std::vector<double> eval_h(2*k_keep, 0.0);        // real and imaginary parts alternate
  std::vector<double> evec_h(n_local*k_keep, 0.0);   // the first n_local elements are the initial vector
  for(PARCEL_INT i = 0; i < n_local; i++){
    double g = (double)(nstart + i);
    evec_h[i] = 1.0 + 0.5*std::sin(0.317*g + 0.7) + 0.3*std::cos(0.181*g - 1.3);
  }
  parcel::vector<parcel_double> eval(2*k_keep,&q), evec(n_local*k_keep,&q);
  eval.setValue(eval_h.data());
  evec.setValue(evec_h.data());
  q.wait();
  ks.solver<parcel_double, parcel_double, parcel_double>(A, eval, evec);
  eval.getValue(eval_h.data());  evec.getValue(evec_h.data());  q.wait();

  if(myrank == 0){
    std::cout << "ks_arnoldi: " << parcel::krylov::converged_reason_name(ks.get_converged_reason())
              << ", restarts = " << ks.get_iterations()
              << ", converged pairs = " << ks.get_ks_nconv() << "/" << nev << std::endl;
    for(int j = 0; j < nev; j++)
      std::cout << "lambda_" << j << " = " << eval_h[2*j] << " + i " << eval_h[2*j+1] << std::endl;
  }
  MPI_Finalize();
  return 0;
}

5.1.2 Setting the Matrix

Create a parcel::matrix<T> (T is the storage precision) and register the CRS matrix of the locally owned rows with set_crsMat<Ttype>(comm, nstart, nend, n, nnz, rowptr, crsCol, val). Ttype is the type of the input array val; the values are converted to T on registration.

  • rowptr : length n+1. Local row pointer in which the first locally owned row starts at 0.
  • crsCol : length nnz. Global 0-based column indices.
  • n, nnz : the number of locally owned rows (= nend−nstart+1) and the number of nonzero elements in the locally owned rows.

set_crsMat() overwrites crsCol and val in place (it converts the column indices to local indices and, in each row, reorders the entries so that columns owned by the rank come first and halo columns come after). rowptr is not modified. If a second matrix (e.g., A−σIA-\sigma I for shift-invert) is created from the same arrays, the column indices are converted twice and the halo exchange breaks in MPI runs. When creating multiple matrices, copy the arrays before the first call to set_crsMat().

set_crsMat() checks the following 4 points before registration. The results of all ranks are gathered by collective communication, and if any check fails, all ranks throw the same std::invalid_argument (the message names the offending ranks and the reason). The checks are made both in the normal version and in the version that takes the high and low parts of double-double as separate arrays.

  1. n == nend - nstart + 1, and at least one row (a rank with 0 rows is not allowed).
  2. rowptr[0] == 0, rowptr is non-decreasing, and rowptr[n] == nnz.
  3. The row blocks of all ranks cover [0,nglobal)[0, n_{global}) without gaps or overlaps (they need not be in rank order).
  4. The column indices lie in [0,nglobal)[0, n_{global}).

The cost is one pass over the nonzeros plus a few collective communications. The checks can be removed with -DPARCEL_NO_CRS_CHECK=1.

In addition, the input CRS must satisfy the following conditions. They are not checked, so violating them can silently give wrong results. The same applies to the C, Fortran and Python APIs.

  • Even for a symmetric matrix, store both the upper and lower triangles (there is no format that stores only one side).
  • Store the diagonal element in every row (even if its value is 0). The Jacobi-type preconditioners use the diagonal elements; a row without its diagonal element makes the preconditioner wrong.
  • Sort the column indices in each row in ascending order, and do not put the same column index twice in a row.

5.1.3 Setting the Vectors

parcel::vector<T> v(n, &q) allocates a vector of length n on the device; setValue(ptr) copies from a host array and getValue(ptr) copies back to the host. The length is the number of locally owned rows. For linear solvers, x in solver(A, x, b) is the initial guess (input) and the solution (output), and b is the right-hand side. For eigenvalue solvers, the second argument holds the eigenvalues and the third the eigenvectors; their sizes differ by solver (see “Calling an Eigenvalue Solver”). The size can be changed with resize(n, &q).

5.1.4 Setting the Preconditioner

The preconditioner is set at run time with member functions of the solver object. This is common to all solvers (including the eigenvalue solvers).

Function Description
set_precon_algo(algo) parcel::PRECON_NONE (0), PRECON_POINTJACOBI (1), PRECON_BLOCKJACOBI (2), PRECON_JACOBI (4)
set_jacobi(iter) Number of iterations of the Jacobi preconditioner (default 1)
set_blockjacobi(nblock) Number of blocks of the block Jacobi preconditioner. If not called, it is determined automatically from the device (CPU: number of threads per rank; GPU: 2 rows per block)
set_scaling_matrix(flag) Scaling of the preconditioner matrix. If not called, automatic (enabled for block Jacobi and half precision, disabled otherwise)
set_scaling_vector(flag) Scaling of the preconditioner vector. Default as above

How to choose a preconditioner on GPUs is shown in “Preconditioners” in “Choosing a Solver”. For the eigenvalue solvers, these settings are used only when set_precon_spectrum(true) is specified, in which case all three solvers return the eigenvalues of AK−1AK^{-1} instead of AA. By default (set_precon_spectrum(false)), the preconditioner settings are not used and the eigenvalues of AA are returned. The preconditioner of the inner linear solver of inverse_power and of the shift-invert of ks_arnoldi is set with separate functions set_linsolve_precon_algo(), set_linsolve_blockjacobi(), set_linsolve_jacobi() (default: Jacobi preconditioner with 1 iteration).

5.1.5 Calling a Linear Solver

All four classes are template<Tspmv, Tprecon, Taxpy, Tdot> and have set_tolerance(tol) (convergence tolerance of the relative residual, default 1.0e-8) and set_max_iteration(itr) (default 10000). The number of template arguments of solver() differs by solver. The template arguments of the class, and those of solver() other than Tmat, Tvecx, Tvecb (which are deduced from the actual arguments), default to parcel_double and can be omitted (e.g., parcel::krylov::pcg<> s; s.solver(A, x, b);).

Class Solver-specific settings Template arguments of solver<...>(A, x, b)
parcel::krylov::pcg None Tmat, Tvecx, Tvecb, Tvec, Tprecon_mat, Tprecon_vec
parcel::krylov::pbicgstab None Same as above
parcel::krylov::pgmres set_restart(m) (default 30), set_qr_algo(algo) (QR_CGS / QR_MGS; default QR_MGS) Same as above + TGS, THessenberg
parcel::krylov::pcagmres set_restart(s,t) (default 8, 4), set_explicit_q(mode) (CAGMRES_Q_AUTO / CAGMRES_Q_EXPLICIT / CAGMRES_Q_IMPLICIT; default CAGMRES_Q_AUTO), set_qr_algo(algo) (QR_CGS / QR_MGS / QR_CHOLESKYQR / QR_CAGMRES_CHOLESKYQR; default QR_MGS. With CAGMRES_Q_IMPLICIT, QR_CHOLESKYQR or QR_CAGMRES_CHOLESKYQR, and QR_CHOLESKYQR if not specified) Same as above + Tbasis, TcalcQR, THessenberg [, Todd_basis, Teven_basis] 
parcel::krylov::pgmres<parcel_double,parcel_double,parcel_double,parcel_double> gm;
gm.set_restart(8);
gm.set_qr_algo(parcel::qr::QR_MGS);
gm.set_tolerance(1.0e-9);
gm.set_max_iteration(10000);
gm.set_precon_algo(parcel::PRECON_JACOBI);
gm.solver<parcel_double,parcel_double,parcel_double,parcel_double,
          parcel_double,parcel_double,
          parcel_double,parcel_double      // TGS, THessenberg
          >(A, x, b);
if(!gm.is_converged() && myrank == 0){
  std::printf("pgmres: %s, its = %d, residual = %.3e, true residual = %.3e\n",
              parcel::krylov::converged_reason_name(gm.get_converged_reason()),
              (int)gm.get_iterations(), gm.get_residual(), gm.get_true_residual());
}

solver() throws no exception and returns no error even if it does not converge, so check is_converged() (or get_converged_reason() > 0) before using the result. The value is the same on all ranks. The meanings of get_iterations(), get_residual(), and get_true_residual() differ by solver (“Convergence Status Constants and Standard Output” in the API Reference). The iteration history and the computation times are printed to the standard output of rank 0.

When an out-of-range value is given to a setter function (set_tolerance(0.0), set_precon_algo(3), set_restart(0), etc.), or when a check at the entry of solver() (an in-order queue, the subspace size of ks_arnoldi, the combination of the way QQ is formed and the QR factorization of pcagmres, etc.) is violated, std::invalid_argument is thrown. The list of checked values is given in “Handling of Settings and Exceptions” in the API Reference.

If device memory cannot be allocated, the library throws util_sycl::device_bad_alloc (derived from std::bad_alloc; what() gives the requested number of bytes and the place of the allocation). The allocation often fails on only some of the ranks, while the other ranks wait in the next collective communication. Do not catch the exception and continue; stop the whole job, e.g., with MPI_Abort().

5.1.6 Calling an Eigenvalue Solver

Eigenvalue solvers are called in the form solver(A, EigenValue, EigenVec). The template arguments of the class are the same as for the linear solvers, <Tspmv, Tprecon, Taxpy, Tdot>.

Class What is computed Size of EigenValue Size of EigenVec Template arguments of solver
parcel::krylov::power One real eigenvalue of largest magnitude 1 or more (stored at the beginning) n Tmat, Teigen_val, Teigen_vec, Tvec, Tprecon_mat, Tprecon_vec
parcel::krylov::inverse_power One real eigenvalue of smallest magnitude 1 or more (stored at the beginning) n Same as above
parcel::krylov::ks_arnoldi nev eigenvalues of largest magnitude (or those near σ) 2·k_keep (real and imaginary parts alternate) n·nev or more (min(k_keep, size/n) vectors are written; on input, the first n elements are the initial vector) Tmat, Teigen_val, Teigen_vec [, Tprecon_mat, Tprecon_vec]

power and inverse_power generate the initial vector internally, so the input values of EigenVec are not used. The convergence criterion (set_tolerance) is the relative change of the eigenvalue for power / inverse_power, and the Ritz residual ∥Av−λv∥/(|λ|∥v∥)\|Av-\lambda v\|/(|\lambda|\|v\|) for ks_arnoldi. When eigenvalues form a complex conjugate pair, the corresponding eigenvector is stored as two vectors, its real part and imaginary part.

// Power method (for the inverse power method, just replace power with inverse_power)
parcel::krylov::power<parcel_double,parcel_double,parcel_double,parcel_double> pw;
pw.set_tolerance(1.0e-9);
pw.set_max_iteration(2000);
pw.set_precon_spectrum(false);   // default: eigenvalues of A. The preconditioner settings are not used in the outer iteration
parcel::vector<parcel_double> lam(1,&q), v(n_local,&q);
pw.solver<parcel_double,parcel_double,parcel_double,
          parcel_double,parcel_double,parcel_double>(A, lam, v);
double lam_h;  lam.getValue(&lam_h);  q.wait();
if(!pw.is_converged()){ /* not converged (DIVERGED_ITS, etc.). pw.get_residual() is the relative change of the eigenvalue */ }

The solver-specific settings are as follows.

  • Common to the 3 solvers : with set_precon_spectrum(true), the eigenvalues of AK−1AK^{-1} are returned (KK is built from AA by set_precon_algo() and related functions). By default (false), the eigenvalues of AA are returned and KK is not used in the outer eigenvalue iteration.
  • inverse_power : the inner linear solver is right-preconditioned pgmres by default, controlled by set_linsolve_tolerance(tol) (default 1.0e-10), set_linsolve_max_iteration(itr) (default 5000), set_linsolve_restart(m) (default 30), set_linsolve_precon_algo(algo) (default parcel::PRECON_JACOBI with 1 iteration), set_linsolve_blockjacobi(nblock), and set_linsolve_jacobi(iter). It can be switched to pcg with set_linsolve_algo(parcel::krylov::LINSOLVE_PCG) (when AA is symmetric definite; with set_precon_spectrum(true), pgmres is always used).
  • ks_arnoldi : set_ks_subspace(m, k_keep, nev) (default 30, 10, 4; std::invalid_argument unless 1≤nev≤kkeep<m1 \leq nev \leq k_{keep} < m), set_ks_max_restart(R) (default 200), orthogonalization set_qr_algo(algo) (parcel::qr::QR_CGS for CGS2 (default), QR_MGS for MGS2; “Default Orthogonalization of ks_arnoldi”). Eigenvalues near σ are computed by shift-invert. Call set_shift(σ) and pass A−σIA-\sigma I as the fourth argument (the preconditioner KinK_{in} of the inner linear solver is built from this matrix). If the fourth argument is omitted, the problem is solved from AA and the shift σ (then Kin=IK_{in} = I, and set_linsolve_precon_algo() is not used). The inner pgmres is controlled by the same set_linsolve_* functions as inverse_power (the default maximum number of iterations is 2000) (the deprecated aliases set_shift_linsolve_tolerance, set_shift_linsolve_max_iteration, set_shift_linsolve_restart can also be used). When combined with set_precon_spectrum(true), the eigenvalues of AK−1AK^{-1} near σ are returned and the fourth argument is not needed.
// shift-invert: register A - σI from separate arrays (because set_crsMat overwrites its arrays)
// copy the originals (col, val) before calling set_crsMat for A
std::vector<PARCEL_INT> col0 = col;
std::vector<double>     val0 = val;
// ... A.set_crsMat(..., col.data(), val.data()) ... (col and val are overwritten)
std::vector<PARCEL_INT> col_s = col0;
std::vector<double>     val_s = val0;
const double sigma = -13.0;
for(PARCEL_INT i = nstart; i <= nend; i++)
  for(PARCEL_INT p = rowptr[i-nstart]; p < rowptr[i-nstart+1]; p++)
    if(col_s[p] == i){ val_s[p] -= sigma; break; }
parcel::matrix<parcel_double> As(&q);
As.set_crsMat<double>(&comm, nstart, nend, n_local, col_s.size(),
                      rowptr.data(), col_s.data(), val_s.data());

ks.solver<parcel_double,parcel_double,parcel_double>(A, eval, evec, &As);
if(!ks.is_converged() || ks.get_linsolve_failures() > 0){
  /* outer iteration not converged, or inner pgmres not converged (revise set_linsolve_*) */
}

For the eigenvalue solvers, too, check convergence with is_converged() and related functions. get_ks_nconv() of ks_arnoldi is the number of eigenpairs (out of nev) that satisfy the tolerance. 5.1.7 Specifying Precision

Precision is specified with template arguments. The types are parcel_fp16, parcel_float, parcel_double, and parcel_doubledouble.

  • Data precision : T of parcel::matrix<T>, parcel::vector<T>, and solver<Tmat, Tvecx, Tvecb, Tvec, ...>.
  • Arithmetic precision : Tspmv, Taxpy, Tdot of the class.
  • Preconditioner : Tprecon of the class (arithmetic precision) and Tprecon_mat, Tprecon_vec of solver (data precision).

The template arguments can be omitted, and an omitted precision becomes parcel_double. This applies to parcel::matrix<>, parcel::vector<>, the 4 arguments of the class, and the data precisions of solver() that cannot be deduced from the actual arguments (Tvec, Tprecon_mat, Tprecon_vec, TGS and THessenberg of pgmres, and Tbasis, TcalcQR, THessenberg of pcagmres) (for ks_arnoldi, Tprecon_mat and Tprecon_vec default to Teigen_vec). For example, parcel::krylov::pcg<> s; s.solver(A, x, b); solves everything in double precision, and the eigenvalue solvers can also be written as s.solver(A, ev, evec). The meaning of explicitly given arguments does not depend on whether others are omitted.

The verification sample (tests/verify/parcel_krylov_sample_verify.cpp) and the C / Fortran wrapper give these through the macros parcel_solver_data_type, parcel_solver_calc_type, parcel_solver_calc_precon_type, parcel_solver_data_precon_mat_type, parcel_solver_data_precon_vec_type (all default to parcel_double), which can be changed with -D. The restrictions at low precision and with double-double are given in “Known Limits at Low Precision” and “double-double”, and the reason -ffast-math cannot be used in “Do Not Use -ffast-math”.

5.1.8 MPI Decomposition

The matrix is partitioned into row blocks. Each rank owns contiguous rows nstart to nend (0-based, inclusive) and holds the CRS of those rows and vectors of length nend−nstart+1. The number of rows may differ between ranks (in the example above the last rank takes the remainder). The row blocks need not be in rank order, but together they must cover [0,nglobal)[0, n_{global}) without gaps or overlaps, and every rank must own at least one row. set_crsMat() checks this (“Setting the Matrix”). The halo exchange tables are built automatically by set_crsMat() from the column indices (for how this works, see “GPUs, MPI Ranks and Data” in the “Basic Structure” chapter). Communication uses the MPI communicator passed to parcel::comm; communicators other than MPI_COMM_WORLD can also be specified.

5.1.11 Passing Your Own Matrix

The matrix passed to PARCEL is the CRS of the rows owned by each rank (the format is in “Data Structures” in “Basic Structure”). This section shows how to bring the matrix of your own problem into this form.

5.1.11.1 Building CRS from Triplets (COO)

Finite element codes and others often assemble a matrix as (row, column, value) triplets (COO format). The following function builds CRS from the triplets of the owned rows. It sorts the triplets by row and column and sums the values of repeated (row, column) pairs (accumulation of element contributions). The result has ascending column indices without duplicates in each row, as PARCEL requires.

#include <algorithm>
#include <vector>
#include "./Include/parcel_sycl.hpp"   // PARCEL_INT

struct Triplet { PARCEL_INT row, col; double val; };   // row and column are global, 0-based

// Build CRS (rowptr, col, val) from the triplets t of the owned rows [nstart, nstart + n_local)
void coo_to_crs(PARCEL_INT nstart, PARCEL_INT n_local, std::vector<Triplet> t,
                std::vector<PARCEL_INT>& rowptr, std::vector<PARCEL_INT>& col,
                std::vector<double>& val)
{
  std::sort(t.begin(), t.end(), [](const Triplet& a, const Triplet& b) {
    return a.row != b.row ? a.row < b.row : a.col < b.col; });
  rowptr.assign(n_local + 1, 0);
  col.clear();
  val.clear();
  for (size_t k = 0; k < t.size(); ++k) {
    if (k > 0 && t[k].row == t[k-1].row && t[k].col == t[k-1].col) {
      val.back() += t[k].val;              // sum repeated (row, column) pairs
      continue;
    }
    col.push_back(t[k].col);
    val.push_back(t[k].val);
    rowptr[t[k].row - nstart + 1]++;       // count the nonzeros of each row
  }
  for (PARCEL_INT i = 0; i < n_local; ++i) rowptr[i + 1] += rowptr[i];
}
  • Pass only the triplets of the owned rows (nstart <= row < nstart + n_local).
  • If some rows may lack a diagonal entry, first add (i, i, 0.0) to every row (the diagonal is stored even when its value is 0).
  • Even for a symmetric matrix, include the entries of both the upper and lower triangles.

5.1.11.2 Reading a Matrix Market File

The Matrix Market format (extension .mtx) is a text format for exchanging sparse matrices. The main points for reading it:

  • A file in coordinate form (coordinate) starts with a header such as %%MatrixMarket matrix coordinate real general, followed by comment lines starting with %, a line “rows columns nonzeros”, and then one “row column value” (1-based) per line.
  • If the header says symmetric, the file contains only one triangle (usually the lower one). Add each off-diagonal entry also at (column, row) with the same value to obtain both triangles (with the sign reversed for skew-symmetric).
  • The pattern (no values) and complex formats cannot be handled by PARCEL (PARCEL solves real matrices).
  • Subtract 1 from the row and column to make them 0-based, keep only the triplets of the owned rows, and convert them to CRS with coo_to_crs above.

5.1.11.3 Distributing a Global Matrix to the Ranks

With MPI, each rank passes only the CRS of its own rows to set_crsMat(). There are two ways to prepare it.

  • Each rank builds only its own rows: if the matrix can be generated from formulas, as with finite differences, each rank generates only the range of its own rows. No rank holds the global matrix, so memory is smallest. The bundled examples (examples/quick_start.cpp, examples/example_pcg_ks.cpp) take this form.
  • Take the owned rows from a global matrix: if a global CRS (grp, gcol, gval, 0-based) is at hand, for example read from a file, the part of rows nstart to nend is a contiguous range of the arrays (from grp[nstart] up to just before grp[nend + 1]). The local row pointers are grp[nstart + i] - grp[nstart], and the column indices are passed as global ones. Either every rank reads the same file and keeps only its rows, or one rank reads it and distributes it with MPI_Scatterv.

set_crsMat() overwrites the column-index and value arrays passed to it (“Setting the Matrix”), so copy the part taken from the global arrays into separate arrays before passing it.

// Take rows [nstart, nend] from a global CRS (0-based), copy them into separate arrays and register them
const PARCEL_INT off = grp[nstart], n_local = nend - nstart + 1;
std::vector<PARCEL_INT> rowptr(n_local + 1);
for (PARCEL_INT i = 0; i <= n_local; ++i) rowptr[i] = grp[nstart + i] - off;
std::vector<PARCEL_INT> col(gcol.begin() + off, gcol.begin() + grp[nend + 1]);
std::vector<double>     val(gval.begin() + off, gval.begin() + grp[nend + 1]);
A.set_crsMat<double>(&comm, nstart, nend, n_local, col.size(),
                     rowptr.data(), col.data(), val.data());

5.1.11.4 Choosing the Partition

The rows of each rank need only be contiguous, and the number of rows may differ between ranks (“MPI Decomposition”). Decide the partition considering the following.

  • Most of the time of an iteration is spent in the SpMV and the preconditioner, whose cost is proportional to the number of nonzeros. In collective operations such as dot products all ranks wait for the slowest one, so for matrices whose number of nonzeros per row varies widely, balance the number of nonzeros rather than the number of rows. With the global row pointer grp, let the first row of rank pp (p=0,1,…,P−1p = 0, 1, \ldots, P-1) be the first row at which the cumulative number of nonzeros reaches p×nnz/Pp \times nnz/P (leave at least one row to each rank).
  • For matrices with nearly the same number of nonzeros per row (such as finite-difference grids), dividing the rows evenly is enough.
  • The amount of halo communication is determined by the number of nonzeros that refer to columns of other ranks. For grid problems, numbering nearby grid points with nearby row numbers (a careful choice of numbering) reduces the halo.
  • The memory of each rank is also roughly proportional to the number of nonzeros of its rows. If GPU memory is insufficient, increase the number of ranks (GPUs) to reduce the rows per rank.

5.2.2 Setting the Matrix

Each rank passes a row block with contiguous global row indices [nstart, nstart + n_local - 1] in CRS format. The meanings of the arguments (n_local, nstart, n_global, nnz_local, rowptr, col, val) are given in parcel_solve_linear() in the Reference. nstart and col are numbered according to index_base, and col holds global column indices. Only differences from rowptr[0] are used for the row pointer.

The integers are of type parcel_int (defined as int64_t in parcel_sycl_c.h; 64 bits). They are 64 bits regardless of the library’s internal PARCEL_INT, and the row pointer and column index arrays must also be allocated as parcel_int (an int array cannot be passed). If the wrapper is built with -DPARCEL_INT32 (“Integer Type” in “Installation”) and a value does not fit in 32 bits, PARCEL_ERR_ARG is returned on all ranks before the arrays are allocated. The fields of parcel_options and parcel_result and the return value of parcel_eigen_count() are int. Build the wrapper, parcel_sycl_mod.f90 and your program with the same version of parcel_sycl_c.h. The wrapper copies the input arrays before registering them, so col and val are not modified. Another solver may be called subsequently with the same arrays. At the call, the wrapper checks that the row pointer is non-decreasing with rowptr[n_local] - rowptr[0] == nnz_local, and that the column indices and the row range lie within [0,nglobal)[0, n_{global}); otherwise it returns PARCEL_ERR_ARG. In each row, the column indices must be in ascending order without duplicates, the diagonal element must be present (even if its value is 0), and both triangles must be stored even for a symmetric matrix (“Data Structures” in “Basic Structure”).

/* sample_c.c: build the CRS of global rows [rstart, rstart+nrow) with 0-based indices (only count if col == NULL) */
static parcel_int poisson_rows(parcel_int nx, parcel_int rstart, parcel_int nrow,
                               parcel_int *rowptr, parcel_int *col, double *val){
  parcel_int nnz = 0;
  rowptr[0] = 0;
  for(parcel_int r = 0; r < nrow; r++){
    const parcel_int g  = rstart + r;
    const parcel_int ix = g % nx, iy = (g / nx) % nx, iz = g / (nx * nx);
#define PUT(c, v) do{ if(col){ col[nnz] = (c); val[nnz] = (v); } nnz++; }while(0)
    if(iz > 0)      PUT(g - nx * nx, 1.0);
    if(iy > 0)      PUT(g - nx, 1.0);
    if(ix > 0)      PUT(g - 1, 1.0);
                    PUT(g, -6.0);
    if(ix < nx - 1) PUT(g + 1, 1.0);
    if(iy < nx - 1) PUT(g + nx, 1.0);
    if(iz < nx - 1) PUT(g + nx * nx, 1.0);
#undef PUT
    rowptr[r + 1] = nnz;
  }
  return nnz;
}

5.2.3 Setting the Vectors

All vectors are the local parts for the locally owned rows and are passed as double arrays. Transfer to the device and copy-back are done inside the wrapper.

  • Linear solvers: b (length n_local) is the right-hand side; x (length n_local) is the initial guess on input and the solution on output.
  • Eigenvalue solvers: with k = parcel_eigen_count(solver, &opt), allocate 2*k elements for eigval and n_local*k elements for eigvec. k is 1 for power / inverse_power and ks_k_keep for ks_arnoldi (of which only the first ks_nev are guaranteed to have converged).
    • eigval: real and imaginary parts are stored alternately (eigval[2*j] is the real part of the j-th eigenvalue and eigval[2*j+1] its imaginary part). For power / inverse_power, eigval[0] holds the eigenvalue and eigval[1] holds 0.
    • eigvec: column-major; the n_local elements starting at eigvec + j*n_local are the locally owned part of the j-th eigenvector. For a complex-conjugate pair of eigenvalues, the corresponding eigenvectors are stored as two consecutive vectors, the real and imaginary parts.
    • Initial vector: power / inverse_power generate it internally. For ks_arnoldi, by default (eigvec_seed=0) the wrapper generates it from the global row indices, so the result does not depend on how the rows are partitioned. With eigvec_seed=1, the first n_local elements of eigvec are used as the initial vector.

Field Description (default)

5.2.5 Calling a Linear Solver

Give one of PARCEL_SOLVER_PCG, _PBICGSTAB, _PGMRES, _PCAGMRES as solver of parcel_solve_linear(). The fields used in common are tolerance (tolerance, default 1.0e-8), max_iteration (maximum number of iterations, default 10000) and the preconditioner fields; pgmres also uses gmres_restart (default 30) and gmres_qr_algo, and pcagmres uses cagmres_s, cagmres_t (defaults 8, 4), cagmres_qr_algo and cagmres_q_mode (Reference). The iteration history and timings are printed to standard output of rank 0. The convergence status is in res.converged_reason, the number of iterations in res.iterations, and the residuals in res.residual and res.true_residual.

/* From sample_c.c: call the linear solvers with the block Jacobi preconditioner
   (the last two are pcagmres without forming Q; they differ only in the choice of QR factorization) */
const int lin_solvers[6] = { PARCEL_SOLVER_PCG, PARCEL_SOLVER_PBICGSTAB,
                             PARCEL_SOLVER_PGMRES, PARCEL_SOLVER_PCAGMRES,
                             PARCEL_SOLVER_PCAGMRES, PARCEL_SOLVER_PCAGMRES };
for(int s = 0; s < 6; s++){
  parcel_options opt;
  parcel_options_init(&opt);
  opt.tolerance     = 1.0e-9;
  opt.max_iteration = 10000;
  opt.precon_algo   = PARCEL_PRECON_BLOCKJACOBI;
  opt.gmres_restart   = 8;               /* default 30 */
  opt.gmres_qr_algo   = PARCEL_QR_MGS;
  opt.cagmres_s       = 8;
  opt.cagmres_t       = 1;               /* default 4 */
  opt.cagmres_qr_algo = PARCEL_QR_MGS;   /* same as the default */
  if(s == 4){
    /* without forming Q: CholeskyQR. t = 2 also exercises the orthogonalization between blocks */
    opt.cagmres_t       = 2;
    opt.cagmres_q_mode  = PARCEL_CAGMRES_Q_IMPLICIT;
    opt.cagmres_qr_algo = PARCEL_QR_CHOLESKYQR;
  }else if(s == 5){
    /* moment method: A symmetric (holds here), no preconditioner, s even */
    opt.precon_algo     = PARCEL_PRECON_NONE;
    opt.cagmres_t       = 2;
    opt.cagmres_q_mode  = PARCEL_CAGMRES_Q_IMPLICIT;
    opt.cagmres_qr_algo = PARCEL_QR_CAGMRES_CHOLESKYQR;
  }
  for(parcel_int i = 0; i < n_local; i++) x[i] = 0.0;
  parcel_result res;
  const int rc = parcel_solve_linear(lin_solvers[s], &opt, MPI_COMM_WORLD,
                                     n_local, nstart, n_global, nnz_local,
                                     rowptr, col, val, b, x, &res);
  if(rc != PARCEL_OK){ /* argument error, etc. */ }
  else if(res.converged_reason <= 0){      /* not converged (PARCEL_DIVERGED_*) */
    printf("reason = %d, its = %d, residual = %.3e, true residual = %.3e\n",
           res.converged_reason, res.iterations, res.residual, res.true_residual);
  }
}

The legacy API run_parcel_sycl_c(), the C API of v1.0, is also kept for compatibility (pcg only; the settings are determined by compile-time macros of the wrapper; Reference). For new programs, use parcel_solve_linear().

gmres_restart = 8 and cagmres_t = 1 in this example are the values of the verification sample, not the library defaults (30, 4). In your own program, start from the defaults set by parcel_options_init() and change only the fields you need.

5.2.6 Calling an Eigenvalue Solver

Give one of PARCEL_SOLVER_POWER, _INVERSE_POWER, _KS_ARNOLDI as solver of parcel_solve_eigen(). Obtain the number k of returned eigenpairs with parcel_eigen_count() (for ks_arnoldi, the subspace sizes ks_m, ks_k_keep, ks_nev default to 30, 10, 4, the maximum number of restarts ks_max_restart to 200, and the orthogonalization ks_qr_algo is CGS2 with PARCEL_QR_CGS and MGS2 with PARCEL_QR_MGS), and allocate eigval (2*k elements; real and imaginary parts alternating) and eigvec (n_local*k elements; column-major). 5.2.8 MPI Decomposition

Pass an MPI communicator (MPI_Comm) as the third argument comm. Communicators other than MPI_COMM_WORLD can also be specified. Because the functions contain collective operations, call them on all ranks of the communicator with the same solver and options of the same content. The handling of the communicator in a build without MPI is described in “Build without MPI”.

The row block of each rank only needs to consist of contiguous rows, and the number of rows may differ between ranks. The row blocks need not be ordered by rank number, but together the row blocks of all ranks must cover [0,nglobal)[0, n_{global}) without overlaps or gaps. The wrapper gathers (nstart, n_local) of every rank with MPI_Allgather to check this and, if the condition is not met, returns PARCEL_ERR_DISTRIBUTION on all ranks. n_local of each rank must be 1 or greater.

/* From sample_c.c: uneven partition that assigns rows to rank r with weight (r+1) */
const long long W = (long long)np * (np + 1) / 2;
long long acc = 0;
for(int r = 0; r < np; r++){
  const int s = (int)((long long)n_global * acc / W);
  acc += r + 1;
  const int e = (int)((long long)n_global * acc / W);
  displs[r] = s; counts[r] = e - s;
}
const parcel_int nstart  = displs[myrank];
const parcel_int n_local = counts[myrank];

5.2.10 Passing Your Own Matrix

The matrix passed to PARCEL is the CRS of the rows owned by each rank (the format is in “Data Structures” in “Basic Structure”). This section shows how to bring the matrix of your own problem into this form.

5.2.10.1 Building CRS from Triplets (COO)

Finite element codes and others often assemble a matrix as (row, column, value) triplets (COO format). The following function builds CRS from the triplets of the owned rows. It sorts the triplets by row and column and sums the values of repeated (row, column) pairs. The result has ascending column indices without duplicates in each row, as PARCEL requires.

#include <stdlib.h>
#include "parcel_sycl_c.h"   /* parcel_int */

typedef struct { parcel_int row, col; double val; } triplet;   /* row and column are global, 0-based */

static int cmp_triplet(const void *pa, const void *pb){
  const triplet *a = (const triplet *)pa, *b = (const triplet *)pb;
  if(a->row != b->row) return a->row < b->row ? -1 : 1;
  if(a->col != b->col) return a->col < b->col ? -1 : 1;
  return 0;
}

/* Build CRS (rowptr, col, val) from the triplets t[0..nt) of the owned rows [nstart, nstart + n_local) and return the number of nonzeros.
   Allocate n_local + 1 elements for rowptr and nt elements for col and val. t is sorted in place */
parcel_int coo_to_crs(parcel_int nstart, parcel_int n_local, triplet *t, size_t nt,
                      parcel_int *rowptr, parcel_int *col, double *val){
  qsort(t, nt, sizeof(triplet), cmp_triplet);
  for(parcel_int i = 0; i <= n_local; i++) rowptr[i] = 0;
  parcel_int nnz = 0;
  for(size_t k = 0; k < nt; k++){
    if(k > 0 && t[k].row == t[k-1].row && t[k].col == t[k-1].col){
      val[nnz - 1] += t[k].val;            /* sum repeated (row, column) pairs */
      continue;
    }
    col[nnz] = t[k].col;
    val[nnz] = t[k].val;
    nnz++;
    rowptr[t[k].row - nstart + 1]++;       /* count the nonzeros of each row */
  }
  for(parcel_int i = 0; i < n_local; i++) rowptr[i + 1] += rowptr[i];
  return nnz;
}
  • Pass only the triplets of the owned rows (nstart <= row < nstart + n_local), and pass the returned number of nonzeros as nnz_local.
  • If some rows may lack a diagonal entry, first add (i, i, 0.0) to every row (the diagonal is stored even when its value is 0).
  • Even for a symmetric matrix, include the entries of both the upper and lower triangles.

5.2.10.2 Reading a Matrix Market File

The Matrix Market format (extension .mtx) is a text format for exchanging sparse matrices. The main points for reading it with fgets, sscanf, etc.:

  • A file in coordinate form (coordinate) starts with a header such as %%MatrixMarket matrix coordinate real general, followed by comment lines starting with %, a line “rows columns nonzeros”, and then one “row column value” (1-based) per line.
  • If the header says symmetric, the file contains only one triangle (usually the lower one). Add each off-diagonal entry also at (column, row) with the same value to obtain both triangles (with the sign reversed for skew-symmetric).
  • The pattern (no values) and complex formats cannot be handled by PARCEL (PARCEL solves real matrices).
  • Pass the row and column 1-based with opt.index_base = 1, or subtract 1 to make them 0-based. Keep only the triplets of the owned rows and convert them to CRS with coo_to_crs above.

5.2.10.3 Distributing a Global Matrix to the Ranks

With MPI, each rank passes only the CRS of its own rows. There are two ways to prepare it.

  • Each rank builds only its own rows: if the matrix can be generated from formulas, as with finite differences, each rank generates only the range of its own rows. No rank holds the global matrix, so memory is smallest. The bundled examples (examples/quick_start_c.c, poisson_rows in examples/sample_c.c) take this form.
  • Take the owned rows from a global matrix: if a global CRS (grp, gcol, gval, 0-based) is at hand, for example read from a file, the part of rows [nstart, nstart + n_local) is a contiguous range of the arrays. Only differences from rowptr[0] are used and the wrapper does not modify the input arrays, so the middle of the global arrays can be passed as is. Either every rank reads the same file, or one rank reads it and distributes it with MPI_Scatterv.
/* Pass rows [nstart, nstart + n_local) taken from a global CRS */
parcel_int off = grp[nstart];
parcel_int nnz_local = grp[nstart + n_local] - off;
rc = parcel_solve_linear(PARCEL_SOLVER_PCG, &opt, MPI_COMM_WORLD, n_local, nstart, n_global,
                         nnz_local, &grp[nstart], &gcol[off], &gval[off], b, x, &res);

5.2.10.4 Choosing the Partition

The rows of each rank need only be contiguous, and the number of rows may differ between ranks (“MPI Decomposition”). Decide the partition considering the following.

  • Most of the time of an iteration is spent in the SpMV and the preconditioner, whose cost is proportional to the number of nonzeros. In collective operations such as dot products all ranks wait for the slowest one, so for matrices whose number of nonzeros per row varies widely, balance the number of nonzeros rather than the number of rows. With the global row pointer grp, let the first row of rank pp (p=0,1,…,P−1p = 0, 1, \ldots, P-1) be the first row at which the cumulative number of nonzeros reaches p×nnz/Pp \times nnz/P (leave at least one row to each rank).
  • For matrices with nearly the same number of nonzeros per row (such as finite-difference grids), dividing the rows evenly is enough.
  • The amount of halo communication is determined by the number of nonzeros that refer to columns of other ranks. For grid problems, numbering nearby grid points with nearby row numbers reduces the halo.
  • The memory of each rank is also roughly proportional to the number of nonzeros of its rows. If GPU memory is insufficient, increase the number of ranks (GPUs) to reduce the rows per rank.

5.3 Fortran

5.3.1 Overview

From Fortran, use the module parcel_sycl_mod (capi/parcel_sycl_mod.f90) and call the procedures below. They are implemented by the wrapper capi/wrapper_parcel_sycl.cpp, which calls the C++ library; all 7 solvers can be selected at run time.

Procedure Description
call parcel_options_init(opt) Fills the settings derived type parcel_options with the defaults
rc = parcel_solve_linear(solver, opt, comm, ...) Solves the linear system Ax=bAx=b (pcg, pbicgstab, pgmres, pcagmres)
rc = parcel_solve_eigen(solver, opt, comm, ...) Solves the eigenvalue problem Av=λvAv=\lambda v (AK−1AK^{-1} with precon_spectrum=1) (power, inverse_power, ks_arnoldi)
k = parcel_eigen_count(solver, opt) Number k of eigenpairs returned by an eigenvalue solver
parcel_options_check(), parcel_result_check() Whether the sizes of the derived types match the structures of the wrapper (logical)
run_parcel_sycl_f(...) Legacy API (compatibility with v1.0; pcg only)

The solver is specified with constants such as PARCEL_SOLVER_PCG. The constants, the fields of the derived types, and the arguments and return values of each procedure are specified in “Fortran API” in the API Reference. Row and column indices, numbers of rows and numbers of nonzeros are passed as 64-bit integers integer(parcel_int_kind).

The calling sequence is as follows.

  1. In a build with MPI, call MPI_Init first (also when running with one process; not needed in a build without MPI).
  2. Check with parcel_options_check() and parcel_result_check() that the sizes of the derived types match the structures of the wrapper (if not, the versions of the wrapper and the module differ).
  3. Fill the defaults with call parcel_options_init(opt) and change only the needed fields, as in opt%tolerance. Do not use it uninitialized.
  4. Prepare the CRS arrays and vectors of the rows owned by each rank.
  5. Call parcel_solve_linear or parcel_solve_eigen on all ranks of the communicator and check that the return value is PARCEL_OK.
  6. Check with res%converged_reason of the parcel_result passed as the last argument whether the iteration converged (positive means converged). res may be omitted.

Each call creates a SYCL queue (an in-order queue on the default device) and registers the matrix. The device is selected with environment variables of the SYCL implementation such as ACPP_VISIBILITY_MASK. With opt%verbose = 1, rank 0 prints the device name, the solver, the preconditioner and the tolerance.

The defaults set by parcel_options_init are the library defaults (all fields and defaults: parcel_options in the Reference). The procedures check the arguments and report errors through return values (PARCEL_OK or a negative error code). The result of the argument check is the same on all ranks. If an error occurs inside the library (running out of device memory, etc.), all ranks are terminated with MPI_Abort in a build with MPI. The return value does not indicate whether the iteration converged, so check res%converged_reason.

  ! ...
  call parcel_options_init(opt)
  opt%index_base    = 1                  ! pass nstart / col 1-based

  opt%gmres_restart = 8                  ! default 30

       nnz_local, rowptr, col, val, b, x, res)
  if(rc /= PARCEL_OK) then
     ! argument error, etc.
  else if(res%converged_reason <= 0) then
     ! not converged (PARCEL_DIVERGED_*). Inspect res%iterations, res%residual, res%true_residual
  end if

5.3.2 Setting the Matrix

Each rank passes a row block with contiguous global row numbers (n_local rows starting at nstart) in CRS format. The arguments are as follows (details: parcel_solve_linear in the Reference).

Argument Description
n_local Number of rows owned by this rank (1 or more)
nstart Global row number of the first owned row (numbered with index_base)
n_global Number of rows of the whole matrix
nnz_local Number of nonzeros of the owned rows
rowptr(n_local+1) Row pointer; only differences from rowptr(1) are used
col(nnz_local) Global column indices (numbered with index_base)
val(nnz_local) Matrix elements

The integer arguments and the integer arrays (rowptr, col) are integer(parcel_int_kind) (= integer(c_int64_t), 64 bits), and matrix elements are real(c_double) (real(8)). Passing a default integer variable for a value argument does not match the interface and causes a compile error, so declare the variable with integer(parcel_int_kind) or convert it with int(n, parcel_int_kind) when passing it. With opt%index_base = 1, nstart and the column indices col can be passed 1-based in the Fortran convention. Only differences from the first element of the row pointer rowptr are used, so it can remain 1-based with rowptr(1) = 1.

The wrapper copies the input arrays before registering them, so col and val are not modified, and another solver may be called subsequently with the same arrays. At the call, the wrapper checks that the row pointer is non-decreasing with rowptr(n_local+1) - rowptr(1) equal to nnz_local, and that the column indices and the row range lie within the matrix; otherwise it returns PARCEL_ERR_ARG. In each row, the column indices must be in ascending order without duplicates, the diagonal element must be present (even if its value is 0), and both triangles must be stored even for a symmetric matrix (“Data Structures” in “Basic Structure”). If the wrapper was built with -DPARCEL_INT32 (“Integer Type” in “Installation”) and a value does not fit in 32 bits, PARCEL_ERR_ARG is returned on all ranks.

! From sample_f.f90: build the CRS of global rows [rstart, rstart+nrow-1] (1-based) with 1-based indices
!   rstart, nrow, r, g, ix, iy, iz, nnz, rowptr(:), col(:) are integer(parcel_int_kind)
nnz = 0
rowptr(1) = 1
do r = 1, nrow
   g  = rstart + r - 1                  ! 1-based global row
   ix = mod(g-1, nx);  iy = mod((g-1)/nx, nx);  iz = (g-1)/(nx*nx)
   if(iz > 0)      call put(g - nx*nx, 1.0d0)
   if(iy > 0)      call put(g - nx,    1.0d0)
   if(ix > 0)      call put(g - 1,     1.0d0)
                   call put(g,        -6.0d0)
   if(ix < nx - 1) call put(g + 1,     1.0d0)
   if(iy < nx - 1) call put(g + nx,    1.0d0)
   if(iz < nx - 1) call put(g + nx*nx, 1.0d0)
   rowptr(r+1) = nnz + 1
end do

5.3.3 Setting the Vectors

All vectors are the locally owned parts and are passed as real(8) arrays. Transfers to and from the device are done inside the wrapper.

  • Linear solvers: b (length n_local) is the right-hand side, and x (length n_local) is the initial guess on input and the solution on output.
  • Eigenvalue solvers: with k = parcel_eigen_count(solver, opt), allocate eigval(2*k) and eigvec(n_local*k). k is 1 for power / inverse_power and opt%ks_k_keep for ks_arnoldi (of which convergence is guaranteed only for the first opt%ks_nev).
    • The real part of the j-th (1-based) eigenvalue is eigval(2*j-1) and the imaginary part is eigval(2*j). Even for power / inverse_power, eigval needs 2 elements (the imaginary part is 0).
    • The owned part of the j-th eigenvector is eigvec((j-1)*n_local+1 : j*n_local) (column j if declared as eigvec(n_local, k)). For a complex-conjugate pair of eigenvalues, the corresponding eigenvectors are stored as two consecutive vectors, the real and imaginary parts.
    • Initial vector: power / inverse_power generate it internally. For ks_arnoldi, by default (opt%eigvec_seed = 0) the wrapper builds it from the global row numbers, so the results do not depend on the partitioning. With opt%eigvec_seed = 1, the first n_local elements of eigvec are used as the initial vector.

5.3.5 Calling a Linear Solver

parcel_solve_linear is a function returning an integer; give one of PARCEL_SOLVER_PCG, PARCEL_SOLVER_PBICGSTAB, PARCEL_SOLVER_PGMRES, PARCEL_SOLVER_PCAGMRES as solver. 5.3.8 MPI Decomposition

The communicator is passed directly as a Fortran integer handle (such as MPI_COMM_WORLD of the mpi module). Communicators other than MPI_COMM_WORLD can also be passed. The procedures include collective operations, so call them on all ranks of the communicator with the same solver and the same contents of opt. The handling of the communicator in a build without MPI is in “Build without MPI”.

The row block of each rank only needs to consist of contiguous rows, and the number of rows may differ between ranks. The row blocks need not be ordered by rank number, but together the row blocks of all ranks must cover all rows of the matrix without overlaps or gaps. The wrapper gathers (nstart, n_local) of every rank to check this and, if the condition is not met, returns PARCEL_ERR_DISTRIBUTION on all ranks. n_local of each rank must be 1 or greater. When index_base = 1, nstart is also given 1-based.

! From sample_f.f90: assign rows to rank r with weight (r+1)
w = int(nprocs, 8) * (nprocs + 1) / 2
acc = 0
do r = 0, nprocs - 1
   displs(r) = int(n_global * acc / w)
   acc = acc + r + 1
   counts(r) = int(n_global * acc / w) - displs(r)
end do
n_local = counts(myrank)              ! n_global, n_local, nstart are integer(parcel_int_kind)
nstart  = displs(myrank) + 1          ! 1-based

5.3.10 Passing Your Own Matrix

The matrix passed to PARCEL is the CRS of the rows owned by each rank (the format is in “Data Structures” in “Basic Structure”). This section shows how to bring the matrix of your own problem into this form.

5.3.10.1 Building CRS from Triplets (COO)

Finite element codes and others often assemble a matrix as (row, column, value) triplets (COO format). The following subroutine builds a 1-based CRS (to be passed with opt%index_base = 1) from the triplets of the owned rows. Repeated (row, column) pairs are summed and the column indices of each row are sorted. The result has the form PARCEL requires.

! Build a 1-based CRS from the triplets ti(k), tj(k), tv(k) (k = 1..nt) of the owned rows nstart .. nstart+n_local-1 (1-based).
!   Repeated (row, column) pairs are summed and the column indices of each row are sorted. nnz returns the number of nonzeros
subroutine coo_to_crs(nstart, n_local, nt, ti, tj, tv, rowptr, col, val, nnz)
  use parcel_sycl_mod, only: parcel_int_kind
  implicit none
  integer(parcel_int_kind), intent(in)  :: nstart, n_local, nt
  integer(parcel_int_kind), intent(in)  :: ti(nt), tj(nt)
  real(8),                  intent(in)  :: tv(nt)
  integer(parcel_int_kind), intent(out) :: rowptr(n_local+1), col(nt), nnz
  real(8),                  intent(out) :: val(nt)
  integer(parcel_int_kind) :: k, r, p, q, jc, pos(n_local), first(n_local+1)
  real(8) :: v
  ! determine the start of each row from the counts and place the triplets row by row
  first = 0
  do k = 1, nt
     r = ti(k) - nstart + 1
     first(r+1) = first(r+1) + 1
  end do
  first(1) = 1
  do r = 1, n_local
     first(r+1) = first(r+1) + first(r)
  end do
  pos = first(1:n_local)
  do k = 1, nt
     r = ti(k) - nstart + 1
     col(pos(r)) = tj(k)
     val(pos(r)) = tv(k)
     pos(r) = pos(r) + 1
  end do
  ! sort each row by column index (insertion sort), sum equal columns and compact
  nnz = 0
  do r = 1, n_local
     do p = first(r) + 1, first(r+1) - 1
        jc = col(p)
        v  = val(p)
        q  = p - 1
        do while (q >= first(r))
           if (col(q) <= jc) exit
           col(q+1) = col(q)
           val(q+1) = val(q)
           q = q - 1
        end do
        col(q+1) = jc
        val(q+1) = v
     end do
     rowptr(r) = nnz + 1
     do p = first(r), first(r+1) - 1
        if (nnz >= rowptr(r)) then
           if (col(nnz) == col(p)) then
              val(nnz) = val(nnz) + val(p)
              cycle
           end if
        end if
        nnz = nnz + 1
        col(nnz) = col(p)
        val(nnz) = val(p)
     end do
  end do
  rowptr(n_local+1) = nnz + 1
end subroutine coo_to_crs
  • Pass only the triplets of the owned rows (nstart <= ti(k) <= nstart + n_local - 1), and pass the returned nnz as nnz_local.
  • If some rows may lack a diagonal entry, first add (i, i, 0.0) to every row (the diagonal is stored even when its value is 0).
  • Even for a symmetric matrix, include the entries of both the upper and lower triangles.

5.3.10.2 Reading a Matrix Market File

The Matrix Market format (extension .mtx) is a text format for exchanging sparse matrices. The main points for reading it with read statements:

  • A file in coordinate form (coordinate) starts with a header such as %%MatrixMarket matrix coordinate real general, followed by comment lines starting with %, a line “rows columns nonzeros”, and then one “row column value” (1-based) per line.
  • If the header says symmetric, the file contains only one triangle (usually the lower one). Add each off-diagonal entry also at (column, row) with the same value to obtain both triangles (with the sign reversed for skew-symmetric).
  • The pattern (no values) and complex formats cannot be handled by PARCEL (PARCEL solves real matrices).
  • The rows and columns are 1-based, so they can be used as they are with opt%index_base = 1. Keep only the triplets of the owned rows and convert them to CRS with coo_to_crs above.

5.3.10.3 Distributing a Global Matrix to the Ranks

With MPI, each rank passes only the CRS of its own rows. There are two ways to prepare it.

  • Each rank builds only its own rows: if the matrix can be generated from formulas, as with finite differences, each rank generates only the range of its own rows. No rank holds the global matrix, so memory is smallest. The bundled examples (examples/quick_start_f.f90, examples/sample_f.f90) take this form.
  • Take the owned rows from a global matrix: if a global CRS (grp, gcol, gval, 1-based) is at hand, for example read from a file, the part of rows nstart to nstart + n_local - 1 is a contiguous range of the arrays. Only differences from the first element of the row pointer are used and the wrapper does not modify the input arrays, so array elements can be passed as the start. Either every rank reads the same file, or one rank reads it and distributes it with MPI_Scatterv.
! Pass rows nstart .. nstart+n_local-1 taken from a global CRS (1-based) (opt%index_base = 1)
off       = grp(nstart)
nnz_local = grp(nstart + n_local) - off
rc = parcel_solve_linear(PARCEL_SOLVER_PCG, opt, MPI_COMM_WORLD, n_local, nstart, n_global, &
     nnz_local, grp(nstart), gcol(off), gval(off), b, x, res)

5.3.10.4 Choosing the Partition

The rows of each rank need only be contiguous, and the number of rows may differ between ranks (“MPI Decomposition”). Decide the partition considering the following.

  • Most of the time of an iteration is spent in the SpMV and the preconditioner, whose cost is proportional to the number of nonzeros. In collective operations such as dot products all ranks wait for the slowest one, so for matrices whose number of nonzeros per row varies widely, balance the number of nonzeros rather than the number of rows. With the global row pointer grp, let the first row of rank pp (p=0,1,…,P−1p = 0, 1, \ldots, P-1) be the first row at which the cumulative number of nonzeros reaches p×nnz/Pp \times nnz/P (leave at least one row to each rank).
  • For matrices with nearly the same number of nonzeros per row (such as finite-difference grids), dividing the rows evenly is enough.
  • The amount of halo communication is determined by the number of nonzeros that refer to columns of other ranks. For grid problems, numbering nearby grid points with nearby row numbers reduces the halo.
  • The memory of each rank is also roughly proportional to the number of nonzeros of its rows. If GPU memory is insufficient, increase the number of ranks (GPUs) to reduce the rows per rank.

5.4 Python

5.4.1 Overview

From Python, import the package parcel (python/ in the distribution package). The package has its own native layer (libparcel_py.so) that calls the C++ library directly, and is independent of the C / Fortran API (capi/). All 7 solvers can be selected and called at run time. One call creates the SYCL queue, registers the matrix and solves, and returns the solution as a NumPy array. Only double precision (for both data and computation) is available.

The default version without MPI runs as a single process with python script.py and holds the whole matrix and vectors. With the version with MPI (Installation), start the script as mpirun -n 4 python script.py; all ranks make the same calls (collective operations), and each rank holds only the rows it owns (a contiguous row block). The same script runs with both (Running without MPI, Running with MPI). Installation is described in Python Package in “Installation”.

# Solve the 3-D Poisson equation with pcg + block Jacobi preconditioning (python poisson.py; with MPI: mpirun -n 4 python poisson.py)
import numpy as np
import scipy.sparse as sp
import parcel

nx = 32
T = sp.diags([-1.0, 2.0, -1.0], [-1, 0, 1], shape=(nx, nx))
I = sp.identity(nx)
G = (sp.kron(sp.kron(T, I), I) + sp.kron(sp.kron(I, T), I) + sp.kron(sp.kron(I, I), T)).tocsr()
b = G @ np.ones(G.shape[0])                       # the exact solution is all ones

A = parcel.DistributedCSR.from_global(G)         # take the rows owned by this rank
x, info = parcel.solve(A, b[A.local_slice()], method="pcg",
                       precond="block_jacobi", tol=1e-10)
if A.comm.rank == 0:
    print(info.reason, info.iterations, info.true_residual)

5.4.2 Setting the Matrix

A matrix is represented by parcel.DistributedCSR. Each rank holds the CRS of the rows it owns (global rows row_start to row_start + n_local - 1). The layout is the same as scipy.sparse.csr_matrix: indptr is the 0-based local row pointer and indices are the 0-based global column indices.

There are three ways to create it: the constructor from the three CRS arrays, from_scipy() from a scipy.sparse matrix of the owned rows only, and from_global(), which takes the owned rows from the whole matrix (for small problems and tests). The arrays passed are copied, so they may be modified afterwards. The arguments, the attributes (n_local, row_start, n_global, nnz, comm) and the checks are given in parcel.DistributedCSR in the Reference. If the matrix check fails, all ranks raise the same ValueError.

5.4.3 Setting the Vectors

Pass the right-hand side b and the initial value x0 as the owned part (a 1-D array of length A.n_local). The returned solution x is also the owned part. If you hold the whole vector, take the part with b[A.local_slice()]. To obtain the whole solution, gather it with, e.g., mpi4py’s allgather.

5.4.4 Setting the Preconditioner

The preconditioner is chosen with precond ("point_jacobi", "block_jacobi", "jacobi"; the default is no preconditioning), and its settings (iterations of the Jacobi preconditioner, blocks of the block Jacobi preconditioner, scaling) are given in the dictionary precond_options (parcel.solve() in the Reference). For the eigenvalue solvers, the preconditioner is used when precond_spectrum=True (computing the eigenvalues of AK−1AK^{-1}). The preconditioner of the inner linear solver is given with inner_precond and inner_precond_options.

5.4.5 Calling a Linear Solver

x, info = parcel.solve(A, b[A.local_slice()], method="pgmres", restart=60,
                       precond="jacobi", tol=1e-10)
if not info.converged:
    print(info.reason, info.iterations, info.true_residual)

Choose the solver with method ("pcg", "pbicgstab", "pgmres", "pcagmres") and give settings such as the convergence tolerance as keyword arguments. Items given as None take the library defaults. The list of arguments and the defaults are given in parcel.solve() in the Reference. Non-convergence does not raise an exception, so check converged of the returned info (SolveInfo).

5.4.6 Calling an Eigenvalue Solver

Choose "power", "inverse_power" or "ks_arnoldi" with method. values is a 1-D complex array, and vectors is an array of shape (A.n_local, count) whose column j is the owned part of the j-th eigenvector. The arguments (m, k_keep, nev of ks_arnoldi, sigma of shift-invert, inner_* of the inner linear solver, etc.) and the order of the returned values are given in parcel.eigs() in the Reference.

# ks_arnoldi: 4 eigenvalues of largest magnitude; shift-invert: 2 eigenvalues closest to 0

5.4.7 Exceptions

Invalid arguments or settings and a failed matrix check raise ValueError, exceeding the range of the integer type raises OverflowError, a solver excluded from the build raises parcel.NotBuiltError, and other failures raise parcel.ParcelError (list: “Exceptions” in the Reference).

In the version without MPI, these exceptions can be caught in the calling process, and failures inside the library such as running out of device memory also raise parcel.ParcelError. The handling in the version with MPI (errors that raise the same exception on all ranks, and errors that terminate with MPI_Abort) is described in Running with MPI.

5.4.8 Specifying Precision

Both data and computation are fixed to double precision (parcel_double); mixed precision is not available. The input and output arrays are float64.

5.4.9 Running without MPI

Run in the same environment as the build (the AdaptiveCpp and LAPACK libraries must be found; spack load py-parcel-sycl... when installed with spack, or sourcing python/envs/mac_brew.sh on macOS). The number of threads is given by OMP_NUM_THREADS. The device is chosen by the default selector, so when several GPUs are visible, choose the GPU to use with CUDA_VISIBLE_DEVICES or the like.

export CUDA_VISIBLE_DEVICES=0
$HOME/venv_parcel/bin/python script.py

The single process owns all rows (row_start = 0, n_local = n_global; create the matrix with from_global()). parcel.Comm() has rank 0 and size 1, and mpi4py communicators cannot be passed. All exceptions can be caught in the calling process (running out of device memory and the like raise parcel.ParcelError).

AdaptiveCpp prints warnings about unused backends on every call, so the package sets ACPP_DEBUG_LEVEL to 0 unless it is already set.

5.4.10 Running with MPI

Start with mpirun; all ranks make the same calls with the same arguments (collective operations). Give the number of threads with OMP_NUM_THREADS. To assign one GPU to each rank, put a wrapper such as gpu_bind.sh between mpirun and Python.

export OMP_NUM_THREADS=12
mpirun -n 4 ./gpu_bind.sh $HOME/venv_parcel_mpi/bin/python script.py

MPI is initialized at the first call. If mpi4py or another module has already initialized MPI, that is used, and the package calls MPI_Finalize at exit only when it initialized MPI itself.

A communicator is represented by parcel.Comm. parcel.Comm() is MPI_COMM_WORLD, and parcel.Comm(c) accepts an mpi4py communicator. The comm argument of the matrix accepts either a parcel.Comm or an mpi4py communicator; if omitted, MPI_COMM_WORLD is used. comm.rank, comm.size, and comm.allreduce(value, op) (sum, maximum or minimum over all ranks; op is "sum", "max", "min") are available.

Any decomposition into contiguous row blocks is allowed; it may be uneven and need not follow the order of the rank numbers. parcel.partition_rows(n_global, comm) returns (row_start, n_local) of an even decomposition (the remainder is given one row each to the first ranks).

row_start, n_local = parcel.partition_rows(n_global)
# make_rows(row_start, n_local) is a user function returning a scipy.sparse CSR matrix of only the owned rows
#   (shape (n_local, n_global), global column indices)
A = parcel.DistributedCSR.from_scipy(make_rows(row_start, n_local), row_start, n_global)

Errors detected by the library (invalid combinations of settings, the matrix check) raise the same exception on all ranks, so processing can continue after catching them. Python-side checks such as array lengths and value ranges are made on each rank, so if the arguments differ between ranks and only some ranks raise, the remaining ranks wait forever in a collective operation. Other errors (such as running out of device memory) can occur on only some ranks, so a message is printed and all ranks are terminated with MPI_Abort.

5.4.11 Passing Your Own Matrix

The matrix passed to PARCEL is the CRS of the rows owned by each rank (the format is in “Data Structures” in “Basic Structure”). This section shows how to bring the matrix of your own problem into this form.

5.4.11.1 Building CRS from Triplets (COO)

Finite element codes and others often assemble a matrix as (row, column, value) triplets (COO format). Converting a SciPy coo_matrix to CSR sums the values at the same position. Call sum_duplicates() and sort_indices() before passing it, to be safe.

import numpy as np
import scipy.sparse as sp
import parcel

# i, j, v: triplets (row and column are global, 0-based). n_global: number of rows of the matrix
G = sp.coo_matrix((v, (i, j)), shape=(n_global, n_global)).tocsr()
G.sum_duplicates(); G.sort_indices()
A = parcel.DistributedCSR.from_global(G)      # take the rows owned by this rank (all rows without MPI)
  • If some rows may lack a diagonal entry, add zero diagonal entries (i, i, 0.0) to the triplets (the diagonal is stored even when its value is 0; do not call eliminate_zeros(), which removes zero entries).
  • Even for a symmetric matrix, include the entries of both the upper and lower triangles.

5.4.11.2 Reading a Matrix Market File

The Matrix Market format (extension .mtx) is a text format for exchanging sparse matrices. It can be read with SciPy’s mmread. mmread also expands files in symmetric form (symmetric) into both triangles. The pattern (no values) and complex formats cannot be handled by PARCEL (PARCEL solves real matrices).

import scipy.io, scipy.sparse
import parcel

G = scipy.sparse.csr_matrix(scipy.io.mmread("matrix.mtx"))
G.sum_duplicates(); G.sort_indices()
A = parcel.DistributedCSR.from_global(G)      # take the rows owned by this rank (all rows without MPI)

5.4.11.3 Distributing a Global Matrix to the Ranks

With MPI, each rank holds only the CRS of its own rows. There are two ways to prepare it.

  • Each rank builds only its own rows: if the matrix can be generated from formulas, as with finite differences, determine the owned rows with parcel.partition_rows(), build only that range, and pass it with DistributedCSR.from_scipy() (make_rows in “Running with MPI”). No rank holds the global matrix, so memory is smallest.
  • Take the owned rows from a global matrix: if every rank can hold the global matrix, DistributedCSR.from_global() takes the owned rows with an even partition. Take the owned part of vectors such as the right-hand side with b[A.local_slice()].

5.4.11.4 Choosing the Partition

The rows of each rank need only be contiguous, and the number of rows may differ between ranks. from_global() and partition_rows() divide the rows evenly; for another partition, decide the owned rows (row_start, n_local) yourself and pass them with from_scipy(). Decide the partition considering the following.

  • Most of the time of an iteration is spent in the SpMV and the preconditioner, whose cost is proportional to the number of nonzeros. In collective operations such as dot products all ranks wait for the slowest one, so for matrices whose number of nonzeros per row varies widely, balance the number of nonzeros rather than the number of rows. With the row pointer G.indptr of the global matrix G, let the first row of rank pp (p=0,1,…,P−1p = 0, 1, \ldots, P-1) be the first row at which the cumulative number of nonzeros reaches p×nnz/Pp \times nnz/P (leave at least one row to each rank).
  • For matrices with nearly the same number of nonzeros per row (such as finite-difference grids), dividing the rows evenly is enough.
  • The amount of halo communication is determined by the number of nonzeros that refer to columns of other ranks. For grid problems, numbering nearby grid points with nearby row numbers reduces the halo.
  • The memory of each rank is also roughly proportional to the number of nonzeros of its rows. If GPU memory is insufficient, increase the number of ranks (GPUs) to reduce the rows per rank.
